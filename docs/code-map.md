# Code-Map

Feature → Ordner. Bewusst grob, keine Zeilennummern. Stand: Terminal-Dock steht (`src/features/terminal/`), davor Umsetzung — Phasen und Stationen eines Plans samt Zeitleiste, Rückfragen und Lagebericht stehen, ebenso die Constraint-Abläufe (Kanten, Warteschlange, Konfiguration je Station, Werkzeuge, Oberfläche, Ersteller wecken, ADR 061) und „Plane Vorhaben“ (ADR 062) (`src/features/implementation/`, `src-tauri/src/implementation/`), davor Betriebsart Codex samt Übersetzer (`src-tauri/src/codex/`) und Druckmodus steht, davor Autarker Agent samt Web (`src-tauri/src/standalone/`) steht, davor Betriebsart und lokales Modell (LM Studio) — Core (`src-tauri/src/lmstudio/`, `src-tauri/src/agents/claude/local.rs`) und Oberfläche (Einstellungen, Eingabeleiste, Neues Vorhaben, Kopfzeile) stehen; davor Sprachdiktat — Mikrofon in der Eingabeleiste, lokale Erkennung im Core (`src/features/voice/`, `src/stores/voice.ts`, `src-tauri/src/voice/`); davor Meilenstein 6 — Einstellungsseite, Farbschema, virtuelle Listen und sichtbare Fehlersätze stehen (`src/features/settings/`, `src/lib/colorScheme.ts`, `src/stores/sessionErrors.ts`, `src/lib/useActionError.ts`, `src-tauri/src/settings/`); davor Plan „Vorhaben und Sessions“ — Vorhaben, Sessions im Vorhaben und TL;DR stehen in Core und Oberfläche (`src/features/projects/`, `src/features/tldr/`, `src-tauri/src/projects/`, `src-tauri/src/tldr/`); davor Meilenstein 2b — Anhänge, Skills und das Hintergrund-Panel stehen (`src/features/attachments/`, `src/features/skills/`, `src/features/background/`, `src/stores/background.ts`); davor Meilenstein 5 — die Changes-Ansicht (Reiter, Dateibaum, Übersicht, Diff-Ansicht in `src/features/changes/`) steht, ihr Core liest die Änderungen aus Git (`src-tauri/src/changes/`); App-Rahmen, Tokens und Typ-Pipeline stehen (`src/app/`, `src/lib/`, `src/styles/`, `src-tauri/src/commands/`, `src-tauri/examples/`), dazu die Claude-Anbindung im Core (`src-tauri/src/agents/`) und die Sessions samt Chat-Verlauf im Speicher des Core (`src-tauri/src/sessions/`, bis M4 die Datenbank übernimmt); die Oberfläche steht für App-Rahmen, Sessions, Chat-Verlauf und Eingabeleiste (`src/features/sessions/`, `src/features/chat/`, `src/stores/sessions.ts`, `src/stores/chat.ts`, `src/components/`); die übrigen Features und `src-tauri/src/<feature>/` außer `sessions/` folgen — die Tabelle beschreibt dort die Zielstruktur und wird mit dem Code nachgeführt.

## Namensschema (parallel über die Schichten)

Ein Feature heißt in jeder Schicht gleich. Wer den Feature-Namen kennt, kennt die Dateien:

```text
src/features/<feature>/           React-Komponenten und Hooks des Features
src/stores/<feature>.ts           Zustand-Slice (nur flüchtiger UI-Zustand)
src-tauri/src/commands/<feature>.rs   Tauri Commands, die die UI aufruft
src-tauri/src/<feature>/          Fachlogik im Core
src-tauri/src/db/<feature>.rs     SQLite-Zugriffe
```

Features: `projects` (Vorhaben), `terminal`, `sessions`, `tldr`, `chat`, `attachments`, `skills`, `background`, `context`, `usage`, `mcp`, `voice` (Diktieren), `changes`, `review` (Review-Kommentare), `repositories`, `settings`, `lmstudio`, `account` (Claude-Konto), `codex_account` (Codex-Konto), `file_links` (Dateiverweise im Chat), `artifacts` (Artefakte), `git` (Git-Werkzeuge in den Changes), `retro` (Vorhaben-Retro), `archive` (Archiv-Suche und Wiederherstellen), `notices` (Hinweise im Verlauf), `promptcache` (Prompt-Cache je Session; Core als `prompt_cache`), `side` (Nebenfragen), `session_tools` (Session-Werkzeuge), `implementation` (Umsetzung), `agent_types` (Agententypen; die Oberfläche heißt `agenttypes`), `remote` (Fernsteuerung). Querschnitt ohne Feature-Bezug: `agents` (Provider), `standalone` (eigener Agent der Betriebsart Autark), `codex` (Übersetzer der Betriebsart Codex), `worktrees`, `processes`, `filesystem`, `mcp_access` (MCP-Zugang des Verwalters) — nur im Core.

## Wo was wohnt — Faustregeln

- Braucht es Dateisystem, Git, einen Prozess oder die Datenbank? → Core, nie direkt aus React.
- Überlebt der Wert einen App-Neustart? → SQLite über den Core, nicht Zustand.
- Nur für die aktuelle Ansicht (aktive Session, gewählte Datei, offene Ansicht)? → `src/stores/<feature>.ts`.
- Neuer Agenten-Typ? → neues Modul in `src-tauri/src/agents/`, das denselben Provider-Vertrag erfüllt; die UI ändert sich nicht.
- Ein Typ, den UI und Core beide kennen? → im Core definieren, nach `src/lib/bindings/` generieren.
- Neuer Typ über die Tauri-Grenze? → `derive(TS)` im Core, in `gen-bindings.rs` eintragen, `pnpm bindings`.
- Git-Aufruf? → ausschließlich über `src-tauri/src/git/`, nie verstreut `Command::new("git")`.
