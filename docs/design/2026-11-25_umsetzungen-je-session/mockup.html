Umsetzungen je Session, keine Sessions außerhalb eines Ablaufs · Klick-Prototyp (Taiga #217, #216)

Stand 2026-11-24 (Planung 0.78.0). #217: Ein Vorhaben kann mehrere Umsetzungen zugleich haben; jede gehört zu genau einer Session, ihrer Master-Session, und eine Session führt höchstens eine unfertige. #216: Agenten öffnen keine Sessions mehr selbst; Arbeit für andere Sessions läuft nur über Stationen. Klick in der Leiste auf Sessions und Umsetzungen; oben simulierst du, was Agenten aufrufen. Neu Gezeigtes ist gestrichelt umrandet.

Farbschema #44 ruft Station ruft Rückfrage #45 ruft

Zur Entscheidung (Empfehlung jeweils so gebaut)

  1. S2 verwalter_open_session verschwindet aus dem Werkzeugsatz (statt immer abzulehnen). Die zwei Wege nennt der Systemprompt (unten). Die Zeile „Selbstfreigabe für neue Sessions“ entfällt in Übersicht und Einstellungen.
  2. S3 höchstens eine unfertige Umsetzung je Session; nach dem Ende darf dieselbe Session eine neue anlegen. Die Grenze „eine je Vorhaben“ fällt.
  3. S4 Masterwechsel auf eine Session, die schon eine unfertige Umsetzung führt: gesperrt, mit Grund.
  4. S5 Gelöschter oder archivierter Master bleibt „Master ausgefallen“ wie heute.
  5. S6 Eine Station legt keine Umsetzung an.
  6. S7 Eine Session findet „ihre“ Umsetzung: geführte unfertige → ihre Station → ihre Rückfrage → zuletzt geführte, auch fertige; kein Rückfall mehr auf die neueste des Vorhabens.
  7. S8 Der Reiter „Changes“ einer Umsetzung zeigt weiter das ganze Vorhaben und heißt „Changes im Vorhaben“; eine Reichweite nur über die Sessions der Umsetzung wird ein Folge-Ticket.

Systemprompt der Session-Werkzeuge (Ausschnitt, Vorschlag; wird mit Haiku gemessen)

Mit anderen Sessions dieses Vorhabens sprichst du über diese Werkzeuge: mcp__verwalter__verwalter_get_sessions, mcp__verwalter__verwalter_send_message_to, mcp__verwalter__verwalter_get_session_tldr, mcp__verwalter__verwalter_open_session, mcp__verwalter__verwalter_read_message.
